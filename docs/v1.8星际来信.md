# v1.8「星际来信」：把作品交到另一个人手里

## 项目还缺哪一环

v1.6提供了可组合的外观，v1.7让当前轨道可以被手写、比较和续写。下一步有三个有价值的方向：

| 方向 | 当前缺口 | 本次选择 |
| --- | --- | --- |
| 旋律批量编辑 | 逐格写音适合小修改，整句搬移与移调仍费手 | 保留为后续方向，先不扩大单声部编辑规则 |
| 长期草稿 | 手稿随页面结束，跨天继续仍需先应用保存 | 保留为后续方向，需要一起处理容量、来源变化与恢复冲突 |
| 作品分享 | 网页能游玩，朋友却不能通过一个链接听到自己的这张星图；JSON需要额外传文件 | 本次实现，补齐从创作到分享的流程 |

这不是社区或账号系统。想保留一种安静的关系：写下一圈声音，把同一次相遇寄给某个人。

## 信笺怎样使用

在“带走这片星空”中选择“寄出当前星图”。窗口左侧是一张带邮票的信，五条横向星线对应五个声部，位置使用真实发声时间，轻重体现在星点大小；静音或未参与独奏的轨道淡去。卡片使用信中外观，窗口外仍是自己的工作台。

网页版本生成当前页面的游玩链接，作品内容放在`#letter=`片段。离线文件生成SL1信笺码，可让对方在支持来信的版本中粘贴打开。它们不需要账号、后台或外部短链服务；没有上传作品或代替用户发送消息。

打开来信先预览，现有星图、外观、收藏不变，也不自动播放。选择“放到我的唱片机”才替换当前星图，主界面可以一次撤销/重做。可取消采用随信外观；采用时外观单独记住，音乐撤销保留这束光，界面已明确说明。收藏一直留在书架里。

接收或关信会清除地址中的来信片段，避免重载再次弹出；已复制的链接不变。接收后清空旧页面手稿，重新从收到的原轨起笔。手工编辑粘贴框会使旧预览立即失效，须重新展开，避免“改了输入却接收上一封信”。

## SL1 格式

`SL1.<base64url UTF-8 JSON>.<8位十六进制FNV-1a校验>`，整码最多4096字符，粘贴输入最多8192字符。JSON包含标题、BPM、音阶、总音量、回响、五条轨道与SG1外观编号。每轨保留原始长度、相位、浮点增益、静音、独奏；33字符字母表将11种音符状态（包括留白）与3种力度编码为一格，连留白处的合法力度也完整保留。

不对浮点数、节奏或音高量化。校验用于发现复制损坏，不证明作者身份；任何人都可以自己写一封有效信。合法校验也须再通过严格结构、音乐和外观校验；未知版本、超长数据、非法UTF-8/Unicode与损坏内容不会替换工作台。标题用textContent渲染，信笺不执行收到的文字。

分享内容是可读的作品数据，并非加密。只有作品和外观进入信，不包含收藏、观测手记、手稿历史或设备信息。固定格式SL1与外观SG1都作为长期协议保留，未来不要重排字母表含义。

## 本地试玩与发布边界

本版尚未上传。loopback地址只能在本机预览，界面会提示；file入口直接给出信笺码。对方需要v1.8或更新版本。上线后从公开网页生成的链接才适合发给朋友，本次没有改动已发布的v1.7。

`示例作品/v1.8.0/穿过玫瑰星云的信.txt`可在“读一封来信”中粘贴试读，同目录JSON与MIDI来自真实界面导出。它是预设旋律的分享样片，用于验证同一作品的传递，不冒充新创作的完整乐曲。

## 验证资料

纯模型测试覆盖完整表达、Unicode、100份混合周期星图、360种外观、损坏和伪造结构、离线/网页链接。浏览器实测使用独立49923源，未改用户文件源或已发布网页的存储。工具启动和页面命名冲突等修正、尺寸矩阵、最终边界见`验证记录/v1.8.0/验收报告.md`。
